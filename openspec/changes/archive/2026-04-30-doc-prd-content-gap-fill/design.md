## Context

`costcohotdogguide.com` 当前已有 39 个页面上线，覆盖了 PRD 中规划的部分内容（FAQ、营养数据、烹饪教程、商业分析、产品评测等）。但 `doc/` 目录中仍有大量高价值需求未实现，包括：9 个 PRD 规划的缺失页面、7 篇深度转化桥梁文章、3 个交互式数据工具、以及 8 个场景化 Affiliate 产品。本次变更是对这些文档需求的系统性补齐。

## Goals / Non-Goals

**Goals:**
- 补齐 PRD 中规划但未实现的 9 个核心内容页面
- 创建 3 个客户端交互式数据工具
- 落地 7 篇深度转化桥梁文章
- 扩展 Affiliate 产品库至覆盖餐饮场景化推荐
- 完善内部链接网络，建立内容集群权重传递

**Non-Goals:**
- 不更改现有 39 个已上线页面的 URL 或核心内容
- 不引入新的技术框架或构建工具
- 不创建全新的页面类型（沿用现有 Astro 页面模板）
- 不添加后端 API 或数据库（工具数据通过静态 JSON 提供）

## Decisions

### 1. 交互工具：纯客户端 Vanilla JS
- **选择**：营养计算器、价格追踪器、WW 积分计算器均使用纯客户端 JS（无框架）
- **理由**：工具逻辑简单（加减乘除 + DOM 更新），无需引入 React/Vue；保持 Astro 静态站零运行时依赖的理念
- **替代方案**：React 组件——过度工程化，增加 bundle 体积和构建复杂度

### 2. 缺失页面：复用现有页面模板
- **选择**：所有新内容页面复用现有的 `BaseLayout.astro` + `SEO.astro` + `RelatedProducts.astro` 组件架构
- **理由**：保持视觉一致性，减少开发时间；已有模板经过 SEO 优化
- **替代方案**：为每种内容类型创建专用模板——重复劳动，边际收益递减

### 3. 价格历史数据：静态 JSON 预生成
- **选择**：价格历史数据存储在 `src/data/prices-history.json`，构建时嵌入页面
- **理由**：价格数据变化频率低（Costco 40 年未涨价），无需实时 API；静态 JSON 可被 Google 直接索引
- **替代方案**：调用外部价格 API——增加依赖和成本，无实质收益

### 4. 转化桥梁文章：独立页面 vs 博客式文章
- **选择**：每篇桥梁文章作为独立页面（如 `/articles/supply-chain-efficiency/`）而非博客列表
- **理由**：独立页面更利于 SEO（独立标题、描述、URL）；便于后续添加 Affiliate 链接和广告位
- **替代方案**：博客列表页——不利于长尾关键词独立排名

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 19 个新页面导致构建时间显著增加 | 复用现有模板，无新依赖；监控构建时长 |
| 交互工具用户体验差（无框架） | 保持 UI 简单直观，充分测试输入边界 |
| 转化桥梁文章过长导致跳出率高 | 使用目录锚点、FAQ 折叠、图表分割长文 |
| Affiliate 产品过多影响阅读体验 | 每页最多 1 个 RelatedProducts 组件，不超过 4 个产品 |
| 价格历史数据不准确 | 明确标注数据来源和最后更新时间 |

## Migration Plan

1. **Phase 1**：创建 3 个交互式工具组件和数据文件
2. **Phase 2**：补齐 9 个 PRD 缺失页面
3. **Phase 3**：创建 7 篇转化桥梁文章
4. **Phase 4**：扩展 Affiliate 产品数据
5. **Phase 5**：更新导航、sitemap、内部链接
6. **Phase 6**：构建验证、部署
