## Context

`costco-content-funnel-monetization` 变更已交付三层漏斗基础设施（10 个 FAQ 页、3 个教程页、2 个工具页、2 个评测页）。但当前站点的 SEO 策略仍以“想到什么写什么”为主，缺少：
- 系统化的关键词覆盖蓝图
- 内容发布的节奏管控
- 核心页面的标准化内容规格
- 全站内链的自动化规则

本变更承接漏斗基础设施，输出一整套可直接指导内容生产的策略文档和模板。

## Goals / Non-Goals

**Goals：**
- 输出 100 关键词分层矩阵，覆盖 A/B/C 三阶段漏斗
- 输出 30 天内容发布日历（Markdown + 甘特式周视图）
- 输出 4 篇核心页面的详细内容大纲（H2-H3 + 关键词 + 内链锚点 + FAQ 问题）
- 制定 FAQ JSON-LD Schema 模板，所有 FAQ 页面统一 markup 格式
- 建立内部链接框架，定义页面类型间的链接权重和锚文本策略
- 明确 URL 结构决策方案（复用现有 vs 新建 `/hot-dog/` 集群）

**Non-Goals：**
- 不实施任何代码变更（仅输出策略文档和模板）
- 不创建实际页面内容（仅输出大纲和规格）
- 不修改现有 URL（URL 结构仅做规划，实施在后续变更）
- 不涉及外链建设或社交媒体运营策略

## Decisions

**1. 关键词矩阵使用 A/B/C 漏斗分层，而非单纯按搜索量排序**
- *决策*：100 关键词按漏斗阶段分类（A=信息型/KD<15，B=比较型/KD 15-30，C=商业型/KD 30+），每类标注目标页面类型和优先级
- *理由*：漏斗分层确保内容生产与变现路径对齐；单纯按搜索量排序会导致高流量低转化内容扎堆
- *替代方案*：按搜索量降序排列 → 否决，忽略转化意图

**2. 30 天日历采用“内容类型轮换”模式**
- *决策*：日历按周轮换内容类型（Week 1: FAQ 铺量 → Week 2: 核心页面增强 → Week 3: 教程/工具 → Week 4: 评测+优化），避免同类型内容集中发布导致爬取配额浪费
- *理由*：Google 对单一域名短期内大量同类内容的索引可能降权；轮换模式模拟自然增长曲线
- *替代方案*：按优先级顺序一次性发布所有高优先级内容 → 否决，风险高且无法根据数据反馈调整

**3. 核心页面大纲采用“一页一表”格式**
- *决策*：每篇核心页面的大纲用 Markdown 表格 + 层级列表混合格式，包含：目标关键词、H2/H3 标题、字数目标、内链锚点、FAQ 问题、CTA 位置
- *理由*：表格便于快速扫描，层级列表保留内容结构；混合格式兼顾可读性和可执行性
- *替代方案*：纯文本大纲 → 否决，缺少量化指标

**4. FAQ Schema 模板强制使用 JSON-LD 内联脚本**
- *决策*：所有 FAQ 页面的 Schema 以 `<script type="application/ld+json">` 形式直接嵌入页面 `<head>`，不依赖外部 JSON 文件或构建时注入
- *理由*：内联脚本确保 Google 爬取时 100% 可见；外部文件可能因构建配置问题遗漏
- *替代方案*：构建时从 frontmatter 自动生成 Schema → 否决，当前 Astro 项目未配置此功能，增加复杂度

**5. 内部链接框架使用“页面类型权重矩阵”**
- *决策*：内链规则不基于页面级语义匹配，而是基于页面类型（FAQ→教程→评测）的固定权重矩阵，辅以主题标签的次级匹配
- *理由*：页面类型权重确保漏斗路径清晰；主题标签处理跨类型链接（如 FAQ “gluten free” → 教程 “无麸质饮食”）
- *替代方案*：纯语义向量匹配 → 否决，需要 NLP 库，对静态站过重

**6. URL 结构决策作为 Open Question 保留，待数据验证后确认**
- *决策*：本变更仅输出两套 URL 方案的对比文档，不在设计阶段做最终选择
- *理由*：现有 4 个核心页面已有排名数据，新建 `/hot-dog/` 集群会分裂权重；需要 GSC 数据验证后才能决策
- *替代方案*：在设计阶段直接选定方案 A 或 B → 否决，缺乏数据支撑

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|---------|
| 关键词估算 KD 与实际 SERP 竞争不符 | 每批内容上线前用 SEOQuake / Ahrefs 免费版复核前 5 位 DA；KD > 预估 20% 的关键词降级到下一阶段 |
| 30 天日历执行过程中发现内容生产速度慢于预期 | 日历标注 P0/P1/P2 优先级，P2 任务可顺延到下一周期；预留每周 1 天缓冲 |
| 核心页面大纲过于详细导致内容创作僵化 | 大纲中标注“弹性区域”，允许作者在不偏离关键词的前提下调整段落顺序和表达方式 |
| FAQ Schema 模板格式错误导致富媒体摘要无法展示 | 提供验证脚本 `scripts/validate-faq-schema.js`，在 build 前检查 JSON-LD 语法和必填字段 |
| 内链框架权重矩阵导致链接分布过于机械 | 每月人工抽查 5 篇页面的内链分布，根据跳出率和停留时间调整权重系数 |

## Migration Plan

本变更无代码迁移，全部为文档交付。交付流程：
1. 所有策略文档存放在 `doc/content-strategy/` 目录
2. 页面大纲存放在 `doc/content-strategy/outlines/`
3. Schema 模板存放在 `doc/content-strategy/templates/`
4. 日历存放在 `doc/content-strategy/calendar/`
5. 变更完成后，通过 `openspec archive` 归档，文档继续作为项目知识库使用
